Days 3 to 7

The TrainStat start model

One workbook carries the whole modelling track. Days 4 and 5 complete the operating three-statement model. Days 6 and 7 extend it into a project finance model with construction, funding, cover ratios and debt sculpting.

Download TrainStat_StartModel.xlsx

What is in the model

Horizon20 years, modelled quarterly (4 periods a year)
Start date1 July 2021 timeline; acquisition / opening balance (financial close) at 31 Dec 2021; construction quarters are added on Day 6
Revenue driversTrains, arrivals per train, seats (350 domestic, 150 international), occupancy and an average fare of US$7.15 per passenger
Operating costHandling: fixed US$4.5m a year plus US$550 per arrival; O&M fixed US$3.3m a year; a +10% O&M sensitivity input
Working capitalReceivable days 25; payable days 35
Non-current assetsUS$100m opening balance (15-year life); capex of US$0.5–2.0m a year 2023–2029 (5-year life)
Senior debt60% of non-current assets in the start model; all-in rate 6.5%; 360-day count; repayment profiles (7.5, 10, 15 years, and a sculpted profile added on Day 7) chosen by a switch
Tax5% tax depreciation on written-down value; 30% corporation tax; interest is tax deductible; deferred tax unwinds to zero by the end
ValuationShareholder required return 25.25%; NPV and IRR of shareholder cash flow
ScenariosSwitch on InpC: Base; Downside (fare −10%, O&M +10%); Upside (fare +10%). The Track sheet stores key outputs of each run for comparison

Values read from the start model as supplied (constants sheet InpC). Participants change them during the exercises.

What we corrected in the supplied workbook

The workbook distributed as TrainStat_StartModel.xlsx is the corrected version. Changes from the original file supplied to the course:

  1. Ghost formulas removed: seven sheets carried about 1,238,318 formulas and formats out to column XFD (the sheet edge), far beyond the 84-column timeline (J to CO). Trimming them cuts the file from about 6.0 MB to 0.4 MB and makes recalculation take seconds instead of many minutes. The unused scratch sheet 'Temp' (about 50,000 formulas) was removed.
  2. Defined names LIVE_RESULTS, TRACK_ACTIVE and TRK_COMMENT repaired (they pointed at deleted cells); name 'unit' re-pointed from an external link to InpC!F102; sheet-level names on Track that pointed at an external workbook removed; Time print area extended to column CO; external link removed.
  3. Typos corrected: Scenario, arrival, Investment, Accounting, available, period, NPV of ...
  4. Stray zeros removed (Tax C28, C35; InpC row 45; InpS J74).
  5. Total and check ranges extended to column CO (they stopped at BY, BV or CQ): the three FinStat checks now cover every column, Time!H79 now counts the post-forecast flag.
  6. Scenarios made coherent: Upside was worse than Base (2% flat inflation) and Downside equalled Base. Now Base / Downside (fare -10%, O&M +10%) / Upside (fare +10%). O&M sensitivity input (InpC row 46) is now live.
  7. Tax: interest deduction placeholder completed (Tax row 26 = Debt interest). Cash tax now deducts interest, so deferred tax unwinds to zero and nothing is left stranded in retained earnings.
  8. Day count corrected: Time row 30 (days in model period) was period end less period beginning, one day short in every quarter (a 361-day year; Constr already used true days). It is now end less beginning plus 1. Interest, receivables and payables, and every result that depends on them move slightly (for example the start-model NPV by about 0.4%).
  9. Placeholders completed: Debt row 42 and Equity row 22 now take inputs from InpS rows 22 and 23; they flow through the cash cascade (FinStat rows 39 and 43) and the shareholder valuation (Val rows 24 and 27).
  10. FinStat: DSCR block added: debt service, DSCR, minimum, average and whole-life cover.
  11. Calculation mode: the workbook was saved in MANUAL calculation mode, so results stayed stale after switching scenario until F9 was pressed. It is now saved in Automatic mode.

Modelling conventions

  • Inputs, workings, outputs and checks on separate sheets; one formula per row, copied across the timeline.
  • Every run is logged on Track so scenarios can be compared.
  • The balance-sheet check on FinStat must be zero before moving on.
